### Findings

| AC-1 | Accuracy | Error | The "Manual payload" placeholder is declared `disabled`, but the proposal and spec also require the user to *select* it to deselect (no-op returning to manual entry). Browsers and Playwright's `select_option` refuse to select a disabled `<option>`, so the documented deselect path and its scenario are unimplementable as written. Pick one: make the option selectable (non-disabled, styled as placeholder) or drop the deselect behavior. | proposal.md L22-23 ("disabled 'Manual payload' placeholder (default)") and L31-32; spec L45 ("defaulting to a disabled 'Manual payload' placeholder") and L65-72 (Scenario: Deselecting to manual payload preserves the text) |
| FS-1 | Accuracy→Feasibility | Error | The dataset is not shipped by the project's deployment path: the Dockerfile copies only `./app` (plus `pyproject.toml`/`uv.lock`), docker-compose mounts only `/transcripts` and `/app/providers.json`, and no task changes packaging or sets `BENCHMARK_DATASET`. In the built container the default `data/benchmark.jsonl` is absent, so the new endpoint always returns 404. The file is also untracked in git (`?? data/`) and no task commits it, despite design.md asserting "the dataset file ships in the repo". | Dockerfile L18 (`COPY app ./app`), docker-compose.yml L17-32, design.md L144-145, `git status` → `?? data/`, tasks.md has no packaging/commit task |
| AC-2 | Accuracy | Warning | Contradictory rule for the dataset id on result rows: the spec says runs whose payload "was entered manually" SHALL display no id, while the design says manual edits to the textarea after a pick do not clear the stored id (and it is rendered). A picked-then-hand-edited payload therefore satisfies "entered manually" under the spec but shows an id per the design. Scope the spec's "manual" case explicitly (e.g. "no dataset entry currently stored") or drop the design's keep-on-edit rule. | spec L96 ("For runs whose payload was entered manually…") and L107-109; design.md L115-117 ("manual edits to the textarea do not clear it") |
| CM-1 | Completeness | Warning | No task creates the test modules or their fixtures. Tasks only say "verify with pytest" against `tests/test_benchmarks_endpoint.py` and `tests/e2e/test_benchmark_difficulty_picker.py` (referenced in every Test Requirement `File:` field), neither of which exists; nothing tasks the fixture dataset (valid/malformed/missing-field lines) or the e2e missing-dataset setup (`BENCHMARK_DATASET` → nonexistent path). | tasks.md L5-6, L11-15; spec Test Requirement `File:` fields L13, 22, 31, 40, 52, 61, 70, 82, 91, 103, 112, 124; `ls tests/` → no `test_benchmarks_endpoint.py`, `ls tests/e2e/` → no `test_benchmark_difficulty_picker.py` |
| FS-2 | Feasibility | Warning | The design never says to call `updateBenchmarkEnabled()` after programmatically setting `injectionToggle.checked = true`; a programmatic assignment fires no `change` event (the only listener is app.js L1116), so after a successful fetch the payload textarea stays disabled/hidden and "Run benchmark" stays disabled — contradicting the "populates payload + enables injection" scenario. Integration of the new select/re-roll/status-line controls with `updateBenchmarkEnabled`'s governance (e.g. disabled during a run) is also unspecified. | app.js L1045-1061 and L1116; design.md L85-91 ("check the injection toggle (if the existing toggle rules allow…)"); spec L56-58; tasks.md L12 |
| CO-1 | Coherence | Warning | Requirement 5 promises "Run benchmark" stays disabled until a successful fetch or a manual payload makes a run possible again, but the design only restores the disabled state when the failed fetch itself turned the toggle on and the panel is fresh (no models selected, empty payload). With injection already enabled and models selected, a failed re-roll leaves "Run benchmark" enabled and the run can proceed on a stale payload. Only the fresh-panel pre-state is tested. Narrow the requirement to the fresh-panel case or extend the design/task to fully enforce it. | spec L117 and L119-125; design.md L88-91 and L138-140 (Risks bullet); tasks.md L14 |
| VL-2 | Validity | Warning | Requirement 5's clause "until a subsequent successful fetch or a manual payload makes a run possible again" is not measurable: it does not state which preconditions (toggle state, selected models, payload emptiness) constitute "possible", so the only executable criterion is the single fresh-panel scenario. | spec L117 |
| AC-3 | Accuracy | Info | Terminology drift across artifacts: "re-roll button" (proposal L28, design L96) vs "re-roll control" (spec L75); "payload textarea" (design L86) vs "payload field" (spec L45). Use one term per concept. | as cited |
| CM-2 | Completeness | Info | Tasks 1.3 and 3.3 are manual-only smoke checks with no automated counterpart, and the three "Workflow follow-up" items are prose bullets rather than `- [ ]` checkboxes, so OpenSpec progress tracking ignores them (`openspec list` reports 0/11). | tasks.md L7, L21, L23-27 |
| FS-3 | Feasibility | Info | The default dataset path is "the repo's `data/benchmark.jsonl`" — CWD-dependent, unlike the existing overrides (`TRANSCRIPT_DIR=/transcripts`, `PROVIDERS_CONFIG` mounted at `/app/providers.json`). Resolve it independent of CWD (e.g. relative to `__file__`) or document that `data/` must live at `/app/data` (see FS-1). | design.md L55-56; app/persist.py L72-77; docker-compose.yml L32 |
