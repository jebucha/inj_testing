| AC-1 | Accuracy | Warning | Tests assert a `min-height` floor that no requirement mandates | T-WEB-INTERFACE-018 / T-TRANSCRIPT-SUMMARIZATION-061 both check "`min-height` is present" (`specs/web-interface/spec.md` L26-33, `specs/transcript-summarization/spec.md` L71-78); the requirement text says only "small by default … vertically resizable". `min-height: 4rem` exists only in design D2 (`design.md` L34) and tasks 1.1/2.1. Either add the floor to the requirement text or drop the assertion. |
| VL-1 | Validity | Warning | Non-measurable criteria in the modified `web-interface` requirement | "small by default (a fixed compact height, smaller than a typical transcript)" and "enlarge or reduce the panel as needed" (`specs/web-interface/spec.md` L6). "typical transcript" / "as needed" have no bound; the concrete values (14rem default, 4rem floor, no cap) live only in design D2. |
| VL-2 | Validity | Warning | Non-measurable criteria in the modified `transcript-summarization` requirement | "a fixed compact height, smaller than a typical summary" and "enlarge or reduce the panel as needed" (`specs/transcript-summarization/spec.md` L6). Same gap as VL-1; the 10rem default appears only in design D2. |
| AC-2 | Accuracy | Info | Duplicated requirement clause across two capabilities | The identical resize clause ("small by default … vertically resizable … bottom-right resize control, matching the injection payload box … SHALL NOT persist") is copied verbatim into `specs/web-interface/spec.md` L6 and `specs/transcript-summarization/spec.md` L6. Not contradictory; consider a shared cross-reference instead of duplicated prose. |
| AC-3 | Accuracy | Info | Proposal promises a viewport cap that design deliberately does not enforce | Proposal: "the resize can grow the panel as needed (up to the viewport)" (`proposal.md` L22-23). | AC-4 | Accuracy | Info | Terminology drift between artifacts | Proposal uses "transcript display box", "summary box", "payload box" (`proposal.md` L5-26); design/specs/tasks use "panel" and "injection payload textarea" (`design.md` L5). Same concepts, different nouns. |

### Notes

- `openspec validate resizable-transcript-summary-panels --strict` passes.
- Feasibility spot-check: in the installed headless Chromium (Playwright chromium-1248), a `<pre>` styled with `height: 14rem; min-height: 4rem; resize: vertical; overflow-y: auto` reports `getComputedStyle(el).resize === 'vertical'`, `clientHeight` 224px and `scrollHeight` 4741px for 200 lines — the design's core assumption and the new tests' assertions hold in the e2e target.
- All Design references verified: `app/static/style.css` L160-173 (`.transcript-panel`, `max-height: 60vh`), L229-242 (`.summary-text`, `max-height: 40vh`), L310-322 (`.injection-payload`, `resize: vertical`), `* { box-sizing: border-box }` at L14; `app/static/app.js` only resets `scrollTop` (L171, L393); `#transcript-panel` / `#summary-text` are `<pre>` elements in `app/static/index.html` L73/L81.
- Every pre-existing scenario in both base specs (`openspec/specs/web-interface/spec.md` L51-70, `openspec/specs/transcript-summarization/spec.md` L345-410) is reproduced in the deltas; the new test IDs 018 and 061 do not collide with existing IDs.
- No prior audits exist for this change, so regression detection was skipped.
